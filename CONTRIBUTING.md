# Contributing

Human and AI-assisted contributions are welcome. Read [auto-research.md](auto-research.md), choose one of its seven tracks, and inspect existing results before repeating an approach.

## Prepare a contribution

1. State a bounded question and check its track ledger for ongoing work. Coordinate overlapping files through the issue/PR or available collaboration channel.
2. Save the result in `auto-research/general/`, `auto-research/negative-results/`, or `auto-research/reviews/`, using the [result template](auto-research/templates/result.md). Include assumptions, exact scope, source revisions, reproducible commands, and the evidence actually obtained.
3. Update the affected track ledgers and result index. Preserve failed attempts and inherited evidence. A negative or inconclusive result is useful when it explains what failed and how the next attempt should change.
4. Add an accurate credit in [CONTRIBUTORS.md](CONTRIBUTORS.md). For a substantive result, add or update the README contributors table. State human authorship, disclosed AI assistance, inherited work, and review roles separately. Keep contribution/merge state separate from verification.
5. Open a pull request explaining the problem, result, verification performed, limitations, and related tracks. Link the durable result record. Do not claim formal verification unless the exact statement and proof were checked with recorded evidence.

## Evidence and review

Written arguments, symbolic checks, numerical observations, Lean elaboration, kernel replay, and independent mathematical review have different scopes. Report them separately. A conditional lemma remains conditional until its hypotheses are derived for the same Yang–Mills family and hierarchy. The project currently has no mass-gap proof.

Preserve contributors' credit when correcting or superseding their work, with a link to the correction. Do not copy sponsorship arrangements, credits, or verification claims from another project unless they actually apply here.
